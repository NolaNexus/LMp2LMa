## OPEN GAPS

### GAP-1 (HIGH): 31 of 38 notebooks have no recorded execution result
- **Evidence**: `.kilo/execution_report.md` header `- Generated: 2026-11-01T09:37:41`, `- Result: 7/7 passed`, and the table lists only the 7 track-01 notebooks. `tools/execution_sweep.py` iterates all 4 tracks (`tools/execution_sweep.py:19-23`), so the last full sweep was never run or its output was overwritten by a `--only track-01` run.
- **Impact**: Plan Phase 3 gate ("every notebook either executes in QUICK_MODE or is explicitly listed as GPU-only") cannot be certified for tracks 02–04; unknown failures may hide there (e.g. GAP-3's broken module lives in track-03).
- **Acceptance**: Full `QUICK_MODE=1 python tools/execution_sweep.py --quick --timeout 600` run regenerates the report with 38 rows; each failure classified (dependency / network / GPU / bug) and fixed or exempted.

### GAP-2 (HIGH): QUICK_MODE coverage is minimal; network downloads remain
- **Evidence**: `grep -l QUICK_MODE track-*/*.ipynb` → only 4 notebooks (`02_experiment_tracking`, `02_cnn_vision`, `03_rnn_seq`, `12_profiling`); `grep -l "download=True"` → 4 notebooks still hit the network (`02_cnn_vision`, `05_generative`, `06_self_supervised`, `03_quantization`).
- **Impact**: Only the 4-notebook CI subset is hermetic; any attempt to widen CI execution or run offline will fail on downloads, and Phase 3's QUICK_MODE gate is unmet for 34 notebooks.
- **Acceptance**: Every dataset-loading notebook grows a QUICK_MODE synthetic fallback, or is explicitly exempted with a reason (see GAP-5).

### GAP-3 (MEDIUM): `track-03-ml-engineer/monitoring.py` does not parse
- **Evidence**: `python -c "import ast; ast.parse(open('track-03-ml-engineer/monitoring.py').read())"` → `SyntaxError: unterminated string literal (detected at line 131)`. The multiline f-string starting at line 131 is unterminated (`sed -n 128,138p` shows the raw body and a stray `""` terminator). All 9 of ruff's `invalid-syntax` findings come from this file.
- **Impact**: Latent defect — no current importer (grep for `import monitoring|from monitoring` in *.py/*.ipynb: 0 hits), so notebooks carry inline copies instead; the module would raise SyntaxError on first real use.
- **Acceptance**: File parses and is either wired into the drift-monitoring notebook or deleted in favor of the inline implementation.

### GAP-4 (MEDIUM): CI installs from .txt files, not the pip-compile locks
- **Evidence**: `.github/workflows/assessment.yml` "Install dependencies" step: `pip install --extra-index-url … -r requirements-ci.txt -r requirements-assessment.txt`. The committed locks (`requirements-ci.lock`, `requirements-assessment.lock`, `requirements-gpu-cu126.lock`) are unused by CI. There is no plain `requirements-gpu.lock` (only the cu126 variant).
- **Impact**: Reproducibility gap — CI resolves loose constraints, so a upstream release can break CI; the plan's Phase 6.1 acceptance ("CI installs from the locks") is unmet.
- **Acceptance**: CI steps pinned to `.lock` files; naming decision for the GPU lock documented.

### GAP-5 (MEDIUM): No GPU-only / QUICK_MODE exemption policy in conftest
- **Evidence**: `grep -n "GPU|gpu_only|QUICK_MODE" tests/conftest.py` → 0 matches; conftest only registers `notebook`/`slow` markers.
- **Impact**: Phase 3 gate criterion 4 ("explicitly listed as GPU-only in tests/conftest.py, with the reason") is unmet; nothing encodes which notebooks are allowed to skip CI execution.
- **Acceptance**: conftest (or a manifest consumed by the sweep) lists exempt notebooks with reasons.

### GAP-6 (MEDIUM): Grader step in CI is vacuous for tracks 03/04
- **Evidence**: The workflow executes only the 4 fast-subset notebooks into `executed/`, then runs the grader for all 4 tracks against `--notebook-dir executed`. With an empty executed dir the grader returns `Track 4: ML Architect 0/24 NOT_EXECUTED 0.0%` (verified), and the workflow only fails on `status == "ERROR"` — so NOT_EXECUTED passes.
- **Impact**: CI green does not certify tracks 03/04; assessment value is concentrated in 2 of 4 tracks.
- **Acceptance**: Either execute a per-track QUICK_MODE subset before grading, or fail/alert on NOT_EXECUTED beyond an agreed threshold.

### GAP-7 (MEDIUM): capstone/tests not wired into CI
- **Evidence**: assessment.yml "Run unit tests" step: `python -m pytest tests/ -v …` — capstone/tests excluded (plan Phase 5.5 says "Hook it into CI"). The 4 capstone test files pass locally (inside the 102) but CI never runs them.

### GAP-8 (MEDIUM): Pre-commit not installed; ruff gate currently fails
